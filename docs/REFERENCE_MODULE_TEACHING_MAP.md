# Reference Module Teaching Map

Use this map when you know the seam you want to study but do not yet know which module demonstrates it best.

If you want a higher-level explanation of what each checked-in module is for before jumping into individual seams, read [MODULE_GUIDE.md](MODULE_GUIDE.md) first.

If you are evaluating the OSS for the first time rather than extending code immediately, do this before using the seam map:

1. use the full Docker composed path in [`../README.md`](../README.md)
2. sign in with the Development-only bootstrap credential documented there
3. inspect `Platform` first so you can see the live module set and operational shell
4. then return to this map once you know which capability you want to trace in code

## Suggested Reading Order

If you are new to the baseline:

1. Read [`MODULE_GUIDE.md`](MODULE_GUIDE.md) first for the core-vs-teaching split and a first-time walkthrough.
2. Read [`../src/Modules/SampleFeature/README.md`](../src/Modules/SampleFeature/README.md) for the smallest governed EF-backed feature.
3. Move to [`../src/Modules/Blog/README.md`](../src/Modules/Blog/README.md) for the first bounded EF aggregate, scheduling, outbox, and editorial workflow example.
4. Continue to [`../src/Modules/KnowledgeBase/README.md`](../src/Modules/KnowledgeBase/README.md) for a richer end-user module.
5. Finish with [`../src/Modules/Admin/README.md`](../src/Modules/Admin/README.md) for cross-module projections, machine access, recovery, and realtime.

If you are using AI to extend the baseline:

1. Start from the governed scaffold, not these modules.
2. Use this map only after scaffolding, when you need a concrete reference for one capability.
3. Prefer the smallest reference that demonstrates the seam you need before copying a richer module.
4. If you are planning a fork, make the keep/remove decision for the teaching modules explicitly through [`ADOPT.md`](ADOPT.md) before you start deleting reference material ad hoc.
