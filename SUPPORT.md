## When to Open an Issue

Open an issue when you have:

- a reproducible bug
- a documentation gap or misleading instruction
- a feature request tied to a clear user or team need
- a baseline regression in the scaffold, contracts, tests, or runtime workflow

## Before Opening an Issue

- Confirm you are using the supported scripts and workflow documented in the repo.
- Check whether the problem is already explained by a governed rule or ADR.
- Include the exact command, environment, and module or feature area involved.

## Security

Do not use public issues for vulnerability reports. Follow [`SECURITY.md`](SECURITY.md).

## Maintainer Scope

This repository is an OSS baseline, not a managed service. Support is best-effort unless a separate support arrangement is stated elsewhere.
